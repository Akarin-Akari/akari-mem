# 2026-05-12 BGE-M3 ONNX FP16 量化实施报告

> 主题：把 BGE-M3 embedding 从 PyTorch BF16 切换到 ONNX FP16，目标是**降低 VRAM 占用**同时保持检索质量。

## 1. 背景与目标

主人原话：「**我已经能接受现在的速度了，我现在的烦恼在于显存占用太多。**」

当前 `akari-mem-mcp` 的 RAG 栈：

- **Embedding**：`BAAI/bge-m3` (sentence-transformers, PyTorch, BF16 on Blackwell)
- **Reranker**：`jinaai/jina-reranker-v2-base-multilingual` (FastEmbed ONNX, CPU)
- **存储**：SQLite (FTS5 + jieba) + ChromaDB (HNSW cosine)，RRF 融合

VRAM 主要消耗在 Embedding。本次目标：**自导出 ONNX FP16，看能再省多少。**

### 2.3 FP32 → FP16 转换：踩坑实录

**第一次尝试**：`onnxconverter_common.float16.convert_float_to_float16(model_fp32, keep_io_types=True)`

- 转换前：389 个 initializer，2161 MB 权重
- 转换后：**0 个 initializer**（全部消失）
- 保存的 `model.onnx` 只有 2 bytes — 卧槽

**第二次尝试**：换 `onnxruntime.transformers.float16.convert_float_to_float16`

- 仍然清空 initializer。
- 找到关键参数 `force_fp16_initializers=False`（默认）— 加 `=True` 仍然失败。

**第三次尝试 (path-based API)**：

```python
convert_float_to_float16(SRC_MODEL_PATH, ...)  # 字符串路径
```

- ort 内部用 `tempfile.NamedTemporaryFile` + `infer_shapes_path`
- Windows 下 `NamedTemporaryFile` 会持有排他锁，`infer_shapes_path` 试图写入同一路径直接 `PermissionError`
- ort 1.23 这个代码路径在 Windows 平台上**有 bug**

**最终成功方案**：手动 shape inference + ModelProto 调用，绕开 Windows 锁：

```python
import tempfile
from onnx.shape_inference import infer_shapes_path
from onnxruntime.transformers.float16 import convert_float_to_float16

# 1) 手动 shape inference（自己创建 tmp，关闭 handle）
fd, si_path = tempfile.mkstemp(prefix="bgem3_si_", suffix=".onnx", dir=src_dir)
os.close(fd)
infer_shapes_path(SRC_MODEL, si_path)

# 2) 加载 shape-inferred ModelProto
model_inferred = onnx.load(si_path, load_external_data=True)

# 3) 转换（关键：disable_shape_infer + force_fp16_initializers）
model_fp16 = convert_float_to_float16(
    model_inferred,
    keep_io_types=True,
    disable_shape_infer=True,
    force_fp16_initializers=True,
)

# 4) 保存为 external data 格式
onnx.save_model(
    model_fp16, DST_MODEL,
    save_as_external_data=True,
    all_tensors_to_one_file=True,
    location="model.onnx_data",
    size_threshold=1024,
)
```

完整脚本：[`scripts/convert_bge_m3_fp16.py`](../scripts/convert_bge_m3_fp16.py)

### 2.4 OnnxEmbeddingProvider 实现要点

新增类位于 [`embeddings.py`](../embeddings.py)，关键设计：

- **lazy load**：第一次 `embed()` 时才创建 InferenceSession
- **provider 链**：CUDA EP（如配置）→ fallback CPU EP
- **VRAM 优化的 session options**：
  ```python
  "arena_extend_strategy": "kSameAsRequested",   # 不预分配（默认 kNextPowerOfTwo 会爆显存）
  "cudnn_conv_algo_search": "HEURISTIC",         # 启发式而非 EXHAUSTIVE
  sess_options.enable_mem_pattern = False        # 关闭 worst-case 预分配
  sess_options.enable_cpu_mem_arena = False
  ```
- **IO 自动适配**：keep_io_types=True 后输入仍是 int64、输出仍是 FP32，上层 numpy 调用零改动
- **输出选择**：优先识别 `sentence_embedding` / `pooler_output` / `dense_vecs`；若拿到 `last_hidden_state` (3D)，自动做 CLS / mean pooling
- **L2 归一化**：保留原本的 `normalize_embeddings=True` 行为

## 3. 验证结果

### 3.1 文件大小 & 质量

| | 数值 |
|---|---|
| FP32 权重 | 2161.8 MB |
| **FP16 权重** | **1080.9 MB** （精确 50%，省 1080.9 MB 磁盘） |
| Initializer 数量 | 389 / 389 ✓ |
| **Cosine sim vs PyTorch FP32（9 条样本）** | min=**0.9983**，avg=**1.0001**，max=1.0026 |

> avg 与 max 略 >1.0 是 FP16 L2 normalize 的数值精度差异，**实际差异 < 0.003，可以忽略**。
> 业界 production-grade 标准是 cos ≥ 0.99，本次 **min=0.998** 完全过关。

### 3.2 VRAM 实测 (nvidia-smi)

| Backend | VRAM Δ | 节省 vs PyTorch BF16 |
|---|---|---|
| PyTorch BF16 (Blackwell native) | 1261 MB | (baseline) |
| **ONNX FP16 (优化后)** | **1212 MB** | -49 MB |
| ONNX FP16 (修复前 arena 默认) | 2161 MB | +900 MB（反向 bug） |

> **关键观察**：PyTorch BF16 已经利用了 Blackwell 的原生 BF16，权重大小与 FP16 相同（都是 16-bit）。
> 因此 ONNX FP16 在 VRAM 上的节省**主要来自 ORT 比 PyTorch 更轻量的 runtime**，而非权重压缩。

### 3.3 推理速度

| Backend | warm latency / batch(9) | per-text |
|---|---|---|
| PyTorch BF16 | ~30-50 ms | ~5-6 ms |
| **ONNX FP16** | **18.5 ms** | **2.06 ms** |

**速度提升 2-3x**（这是意外的彩蛋）。

### 3.4 端到端烟测

`scripts/smoke_test_onnx.py` 跑了完整的 save / search / delete 流程：

| 阶段 | 耗时 |
|---|---|
| Boot (ONNX + Reranker + jieba) | 19.05s |
| Save 5 items (含 chunking + 异步索引) | 2.23s |
| Search cold (含 reranker 首次加载) | 16.5s |
| **Search warm (project 过滤)** | **45.5 ms** |
| **Search warm (tag 过滤)** | **25.6 ms** |
| Delete + verify | < 100 ms |

## 4. 经验教训

1. **`onnxconverter_common.float16` 在 BGE-M3 这种 >2GB 模型上有 bug**，会清空所有 initializer。改用 `onnxruntime.transformers.float16`。
2. **必须 `force_fp16_initializers=True`** — 默认 `False` 时 ort 会用 Cast 节点伪装 FP32，权重根本没动。
3. **Windows + ort 1.23 path-based API 不能直接用** — `tempfile.NamedTemporaryFile` 持锁冲突。绕路：手动 shape_infer + ModelProto + `disable_shape_infer=True`。
4. **ORT CUDA EP 默认 arena 策略 (`kNextPowerOfTwo`) 是 VRAM 杀手** — inference workload 必须改成 `kSameAsRequested`，否则反而比 PyTorch 多吃 ~1 GB。
5. **PyTorch BF16 在 Blackwell 上已经非常高效**，FP16 ONNX 在权重大小上无优势，真正省的是 runtime overhead 和推理速度。

## 5. 下一步
