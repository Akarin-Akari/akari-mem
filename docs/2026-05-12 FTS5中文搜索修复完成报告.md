## 一、根因分析

### 问题表现
`quick_search` 工具底层使用 SQLite FTS5 (`memories_fts` 虚拟表) 做 keyword 检索。
当 query 是中文复合词时（如 `"代码搜索"`、`"微信小程序"`、`"撤销工具"`），返回 0 hits。

### 根本原因
`store.py` 创建 FTS5 虚拟表时**没有指定 `tokenize` 参数**：

```sql
CREATE VIRTUAL TABLE memories_fts
USING fts5(title, text, tags, content='memories', content_rowid='id')
-- ⚠️ 没有 tokenize 选项，默认走 unicode61
```

SQLite 默认的 `unicode61` tokenizer 行为：
- ✅ 按**空格和标点**拆分单词 → 英文完美
- ❌ **CJK 字符串没有空格，被当成一整个不可分割的 super-token**

因此存了一段 `"代码搜索工具优先级 - 用户强制偏好"`，FTS5 索引里就只有 `代码搜索工具优先级`、`用户强制偏好` 两个 token，查 `"代码搜索"` 必须完整命中整个 token 才行——**子串匹配 100% 失败**。

---

## 二、解决方案

采用 **应用层 jieba 预分词** 方案：
- 写入 FTS5 前用 jieba 切分中文，存成空格分隔的 token 字符串
- 查询前用 jieba 切分 query，再交给 FTS5 MATCH
- FTS5 的 `unicode61` tokenizer 此时只需要按空格分割，刚好契合

### 对比备选方案

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| `tokenize='trigram'` | 零依赖，CJK 友好 | 索引体积大，召回偏差 | ❌ |
| `tokenize='unicode61' + tokenchars` | 配置简单 | 仍无法正确分词 | ❌ |
| **jieba 应用层预分词** | **分词质量最好** | 增加 pip 依赖 | ✅ 选定 |

### tokenizer.py 核心设计

```python
def tokenize_for_fts(text: str) -> str:
    """写入索引时用，cut_for_search 模式（细粒度，提高召回）"""
    if not has_cjk(text):
        return text.strip()
    tokens = jieba.cut_for_search(text)
    return " ".join(t.strip() for t in tokens if t.strip())

def tokenize_query(query: str) -> str:
    """查询时用，精确模式（避免过度切分）"""
    if not has_cjk(query):
        return query.strip()
    tokens = jieba.cut(query, cut_all=False)
    return " ".join(t.strip() for t in tokens if t.strip())
```

**关键设计点**：
1. **懒加载 + 单例**：`_ensure_jieba()` 首次调用时初始化，避免 import 延迟
2. **CJK 检测**：英文文本不走 jieba，零开销
3. **降级容错**：jieba 未安装时退化成原文，搜索功能不报错

## 五、技术亮点

### 1. 零中断重建
独立轻量重建脚本只操作 SQLite，**不加载** BGE-M3 / Qwen3-Reranker 等重模型，从启动到完成 < 3 秒。

### 2. 写入路径双重保护
- `MemoryStore.save()`（API 服务器走的路径）→ 调用 `_fts_insert()` jieba 化
- `server.py::_save_to_sqlite()`（MCP fast-path）→ 也做 jieba 化

两条独立路径都注入了 tokenizer，避免遗漏。

### 3. 查询降级链
```
jieba tokenized query → FTS5 MATCH(AND 语义)
   ↓ syntax error
拆 token 后 OR 拼接 → FTS5 MATCH
   ↓ 仍失败
返回空列表（不抛异常）
```

### 4. 删除路径修正
FTS5 是 `content='memories'` 模式（external content），删除条目必须用 **写入时相同的 tokenized 内容** 才能 sync 成功。`_fts_delete()` 复用了 `tokenize_for_fts` 保证一致性。

## 六、回滚方案

如果 jieba 出现问题需要快速回滚：
1. 删除 `tokenizer.py` 不会让现有代码崩溃（写入侧会 fallback 用原文，但中文搜索回到 0 hits 状态）
2. 卸载 jieba：`pip uninstall jieba`
3. 删除 `data/akari-mem.db` 中的 FTS5 内容并重建：FTS5 仍可工作，只是中文搜索质量回到修复前
